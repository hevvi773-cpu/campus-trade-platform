## Campus Second-Hand Trading Platform | Full-Stack Developer + Product Designer | Jun 2026 – Present

**Live Demo**: http://106.53.27.244 ｜ GitHub: github.com/hevvi773-cpu/campus-trade-platform

A C2C second-hand trading system for university students, solving the pain points of scattered campus second-hand information across QQ groups / campus channels / confession walls, opaque product status, and inconsistent search capabilities across channels. Deployed and live on a public cloud server.

- **Solely responsible for backend + web frontend**: Built full-stack with Flask + MySQL, refactored from a single 7,619-line file into a modular architecture of 9 routes + 11 services, with 15 version iterations each accompanied by a CHANGELOG
- **Complete trading loop**: Implemented product publishing & review (24h auto-approve fallback), order trading (`SELECT ... FOR UPDATE` row-level lock prevents concurrent overselling), in-app messaging (product context cards), review system (buyer rates seller, 1-5 stars), and admin data dashboard — 35 routes, 11 database tables
- **Engineering quality & security**: Fixed P0-level `onclick` quote conflict bug (all admin dashboard buttons failed), homepage 500 hotfix, and confirm_code privilege escalation vulnerability; optimized admin dashboard statistical SQL from 35 to 11 queries; site-wide CSRF protection + login rate limiting (5 failures → 10-min lock) + three-tier permission system
- **Product documentation**: Independently authored an as-built PRD V1.3 (106KB), reverse-engineered from 13 historical versions, including 11-table DDL, API contracts, privacy compliance plan, 20 regression test items, and DEV-001~013 known issues
- **Real data**: Single-person multi-account end-to-end cross-validation with 26 accounts and 51 products, verifying the complete loop: register → publish → review → order → confirm → review

**Tech Stack**: Python / Flask / MySQL / Jinja2 / Bootstrap 5 / Chart.js / gunicorn / systemd
